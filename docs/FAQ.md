# ENTENCY FAQ

## What is ENTENCY?

ENTENCY is an experimental distributed computing ecosystem built around **ENTENCY UP** and **ENTENCY GNS (Global Neural System)**. It explores a unified architecture for execution, storage, communication, streaming, compute and service delivery.

## What is ENTENCY UP?

ENTENCY UP is the user-facing **Browser and Workstation** of the ENTENCY ecosystem. It provides session control, protocol routing, local application execution and access to GNS-native resources and services.

## What is ENTENCY GNS?

ENTENCY GNS — Global Neural System — is the distributed node infrastructure beneath ENTENCY. It provides common foundations for deterministic data/object handling, node communication, storage, communication, streaming, compute and GNS-native service delivery.

## Is the Global Neural System an artificial neural network?

No. **ENTENCY GNS is distributed infrastructure, not an artificial neural network.**

The word "Neural" is part of the network's name and should not be interpreted as a claim that GNS itself is a neural model, LLM, AI-training system or decentralized neural-processing cluster.

ENTENCY's planned AI/intelligence layer is **ENTENCY AXI**, which is a separate concept.

## Is ENTENCY an AI project?

AI is part of the planned broader ecosystem through ENTENCY AXI, but describing the current ENTENCY core simply as an "AI project" would be misleading. The current technical foundation is ENTENCY UP plus the distributed GNS infrastructure.

## Is ENTENCY a blockchain?

ENTENCY should not be reduced to "a blockchain." GNS is designed as distributed execution and service infrastructure with deterministic data, identity, trust and network mechanisms. Individual protocol mechanisms should be described according to their actual implementation rather than assuming that every distributed component is a conventional blockchain.

## Is ENTENCY Web3?

ENTENCY overlaps with some problems often associated with Web3 — distributed infrastructure, identity, verifiable state and network-native services — but its architecture is not defined solely by the Web3 label. UP is also designed to work with the conventional Web.

## Is ENTENCY UP just a browser?

No. Browser functionality is one part of UP. UP also provides a Workstation environment, deterministic session control, protocol routing, local application execution and GNS service integration.

## Is ENTENCY GNS just a peer-to-peer storage network?

No. Storage is one GNS service domain. The architecture also includes foundations for communication, streaming, compute and GNS-native service publication/hosting.

## What is `gns://`?

`gns://` is the GNS-native addressing and navigation scheme used by ENTENCY UP for resources and services resolved through GNS.

## Does `gns://` replace HTTP or HTTPS?

ENTENCY makes no such current production claim. UP is designed to interact with conventional web resources and GNS-native resources. The goal is a unified, protocol-extensible execution environment.

## What is Zero-Config Webhosting?

Zero-Config Webhosting is the GNS service model for publishing and resolving website/application resources through GNS-native infrastructure. Published GNS resources can be opened from ENTENCY UP through `gns://` addressing.

## What services does GNS target?

Current service foundations include:

- Storage
- Communication
- Streaming
- Compute
- Zero-Config Webhosting

Additional service domains may be introduced as the architecture evolves.

## What is ENT?

ENT is the **planned network resource and participation layer** of GNS. Its intended role includes resource metering and participation accounting associated with distributed resource consumption and provision.

ENT should not be confused with the name ENTENCY, and it is not represented as part of the current production-ready core.

## What is ENTENCY Wallet?

ENTENCY Wallet is a planned user-facing identity and network-asset layer. Its final production architecture will evolve with GNS identity, capability and resource-accounting systems.

## What is ENTENCY AXI?

ENTENCY AXI is the planned intelligence layer of ENTENCY. Potential directions include network observation, anomaly detection, security intelligence, routing assistance, resource optimization and user-facing AI capabilities.

AXI is planned; it must not be described as a completed capability of the current core.

## Is ENTENCY open source?

This repository is the public entry point to the ENTENCY ecosystem, but the core engine remains closed during active foundational development. Public documentation should not imply that the complete active implementation is currently open source.

## Is ENTENCY production ready?

No. ENTENCY is under active foundational development and validation. Several architectural foundations are implemented and tested, while internet-scale operation, public-network hardening and other ecosystem layers remain under development.

## Does ENTENCY already have a public GNS network?

The project should currently be described as operating primarily in development/test-network conditions. A production public network is a future stage that depends on further distributed, security, resilience and operational validation.

## What is currently being developed?

Major public-network development areas include NAT traversal, independent-network operation, peer discovery, connection recovery, replication/retrieval hardening, failure recovery, abuse resistance, adversarial testing, long-running stability and public devnet deployment.

## How are capability claims handled?

ENTENCY follows an **evidence-before-claims** principle. Documentation distinguishes between implemented, validated, experimental and planned functionality.

## What is the relationship between UP and GNS?

UP is the user-facing execution and control surface. GNS is the distributed network infrastructure beneath it.

```text
ENTENCY
├── ENTENCY UP  -> Browser + Workstation
└── ENTENCY GNS -> Distributed node infrastructure
```

They are separate systems designed to work together.
