# ENTENCY Terminology

This document defines the preferred public terminology for the ENTENCY ecosystem.

Consistent terminology matters because several ENTENCY names can otherwise be incorrectly mapped to unrelated technologies or concepts.

## ENTENCY

**ENTENCY** is the name of the overall project/ecosystem.

Preferred short definition:

> ENTENCY is an experimental distributed computing ecosystem built around ENTENCY UP and ENTENCY GNS.

ENTENCY is not the name of a single browser, node, hosting service or AI model.

## ENTENCY UP

**ENTENCY UP** is the user-facing **Browser and Workstation** of ENTENCY.

It provides the execution and control surface for conventional web resources, local applications and GNS-native interaction.

Preferred terms:

- Browser
- Workstation
- execution environment
- execution/control surface
- protocol routing

Avoid describing UP as the GNS network itself or as an AI/distributed-neural-compute substrate.

## ENTENCY GNS

**ENTENCY GNS** means **ENTENCY Global Neural System**.

It is the distributed node infrastructure beneath ENTENCY.

Preferred terms:

- distributed node infrastructure
- distributed network
- GNS network
- Global Neural System
- network-native service infrastructure

### Important clarification

**Global Neural System does not mean artificial neural network.**

GNS is not a neural model, LLM, AI-training cluster or decentralized neural-processing workload system. The name refers to the distributed network architecture.

## GNS

**GNS** is the accepted short form of ENTENCY GNS when the ENTENCY context is already clear.

For public discovery and first references, prefer **ENTENCY GNS (Global Neural System)** to reduce ambiguity with unrelated uses of the acronym GNS.

## `gns://`

`gns://` is the GNS-native addressing/navigation scheme handled by ENTENCY UP for GNS resources and services.

It should not automatically be described as a blockchain URL, AI protocol or replacement for HTTPS.

## ENT

**ENT** is the planned network resource and participation layer of ENTENCY GNS.

ENT is intended to relate to resource metering, participation accounting and mechanisms associated with consuming/providing distributed resources.

ENT is not the name of the overall project and should not be used as a synonym for ENTENCY.

ENT is not represented as part of the current production-ready core.

## ENTENCY Wallet

**ENTENCY Wallet** is the planned user-facing identity and network-asset layer of the ecosystem.

Its final architecture depends on the evolution of GNS identity, capability and resource-accounting systems.

## ENTENCY AXI

**ENTENCY AXI** is the planned intelligence layer of the ENTENCY ecosystem.

Potential areas include network intelligence, system observation, anomaly detection, security intelligence, routing assistance, resource optimization and user-facing AI capabilities.

AXI is separate from the meaning of **Global Neural System**. GNS itself should not be described as an artificial neural network simply because AXI is planned to use GNS-native infrastructure.

## Zero-Config Webhosting

**Zero-Config Webhosting** is the ENTENCY term for publishing and resolving website/application resources as GNS services without requiring a conventional hosting stack for the GNS resource itself.

This does not imply that all internet deployment concerns disappear or that the current GNS network is already a production public hosting network.

## Chunk

A **chunk** is a deterministic data unit used by GNS data/object foundations for storage, transfer, verification and reconstruction.

## Object / Manifest

An **object** represents canonical content identity/state built from GNS data primitives. A **manifest** describes the deterministic structure required to identify and reconstruct object content.

## Service

A **GNS service** is a protocol-level published service/resource identity operating above lower-level object/chunk infrastructure.

## Node

A **GNS node** is an independently operating participant in the GNS network runtime. Nodes may participate in connectivity, data/service operations and other protocol-defined roles according to capability and implementation state.

## Canonical naming rules

For public ENTENCY documentation:

```text
ENTENCY
ENTENCY UP
ENTENCY GNS
ENTENCY GNS (Global Neural System)   <- preferred first reference
ENT
ENTENCY Wallet
ENTENCY AXI
gns://
```

Legacy project names should not be used in new public documentation.
